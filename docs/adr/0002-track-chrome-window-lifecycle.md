# ADR-0002: Chromeウィンドウのライフサイクルを追跡する

- Status: Accepted
- Date: 2026-07-22
- Related: SCRUM-12

## Context

MVPは、Chromeがプロファイル選択画面を表示した場合、利用者が選択した後に開く通常のブラウザウィンドウを配置対象とします。

ADR-0001の実機検証では、プロファイル選択画面の消失と通常ウィンドウの出現をポーリングで追跡できました。一方、短時間だけ存在する候補の見落とし、無駄な列挙、同時に開いた別ウィンドウとの競合が残ります。WinEventを使う場合も、イベントだけでは候補の意味、同一性、今回の起動操作との関連を保証できません。

## Decision Drivers

- ウィンドウの変化へ早く反応できること
- イベントの欠落や一時的なハンドルを成功扱いしないこと
- 他のChromeウィンドウを誤って移動しないこと
- プロファイル情報、タイトル、閲覧内容を取得しないこと
- 待機、取消、タイムアウト、失敗時にフックを確実に解除できること
- Windows固有の処理をInfrastructureへ隔離し、状態遷移をApplication層でテストできること

## Considered Options

### Option 1: WinEventだけを使用する

変化を低遅延で検知できますが、イベントは現在の有効な状態や今回の起動操作との因果関係を保証しません。

### Option 2: ポーリングだけを使用する

実装と状態確認は単純ですが、短時間の遷移を見落とす可能性があり、変化がない期間も列挙を繰り返します。

### Option 3: WinEventとポーリングを併用する

WinEventを変化の通知に限定し、イベント受信時と定期間隔でトップレベルウィンドウを再列挙します。

## Decision

Option 3を採用します。

`WINEVENT_OUTOFCONTEXT`でCREATE、DESTROY、SHOWを観測します。コールバックは受信値をキューへ追加するだけにし、Chrome候補の列挙、検証、状態遷移をコールバック外で逐次処理します。低頻度のポーリングは、イベント欠落時の再同期と待機終了条件の判定に使用します。

WinEventは候補を確定する根拠にしません。起動前のスナップショットとの差分を取り、待機終了時に次の情報を再確認します。

- ウィンドウハンドルが有効であること
- Chromeのトップレベルウィンドウであること
- PIDとプロセス開始時刻が一致すること
- ウィンドウクラスと可視性が期待する状態であること
- 起動前に存在しない有効な候補が1つだけであること

候補が複数ある場合、候補の同一性を確認できない場合、または追跡中に予期しない状態へ遷移した場合は配置しません。

フック専用スレッドが登録、メッセージループ、解除を担当します。完了、取消、タイムアウト、失敗のすべての終了経路で、同じスレッドから`UnhookWinEvent`を呼び出します。

プロファイル選択待機には、利用者による取消と60秒の最大待機時間を併用します。タイムアウトは成功として扱わず、入力値を保持して再実行可能な状態へ戻します。

利用者による取消は、端末のCtrl+Cなど実行環境に依存する割り込みではなく、UI操作からInfrastructureへ渡す明示的な取消シグナルとして実装します。

## Consequences

- Infrastructure層はWinEvent、メッセージループ、ウィンドウ列挙、プロセス同一性の取得を担当する
- Application層はイベントの詳細ではなく、スナップショットと状態遷移を扱う
- WinEventが利用できない場合やフック登録に失敗した場合は、成功としてポーリングへ暗黙に縮退せず、明示したフォールバック方針に従う必要がある
- コールバックの再入と高頻度イベントに備え、処理をキューで直列化する必要がある
- 単体テストではイベント順序、イベント欠落、重複、候補競合、取消、タイムアウトを再現する必要がある
- Windows実機ではChrome未起動時と起動済み時の両方を検証する必要がある

## Validation

- [x] Chrome未起動時のイベントとスナップショットを記録できる
- [x] Chrome起動済み時のイベントとスナップショットを記録できる
- [x] プロファイル選択時の候補置き換わりを観測し、最終候補を目視確認できる
- [x] 同時に別ウィンドウが開いた競合状態を再現できる
- [ ] 複数候補を拒否する判定を製品実装の自動テストで確認できる
- [x] 無効になったハンドルが候補から消失することを確認できる
- [ ] 取消と予期しない候補消失を製品実装の結果として区別できる
- [x] 明示的な取消時にフックを解除し、直後に再登録できる
- [x] 60秒のタイムアウト時にフックを解除できる
- [ ] 失敗時にフックを解除できる
- [x] 最大待機時間と利用者への表示を決定できる
