# 開発ガイド

## 目的

このディレクトリは、Browser Launcher の開発を一貫した進め方で行うためのルールと判断基準をまとめます。

本プロジェクトは Go、React、DDD、クリーンアーキテクチャの学習を目的とします。原則を形式的に適用するのではなく、小規模なプロジェクトに必要な範囲で採用し、設計・実装の理由を説明できることを重視します。

## 基本原則

1. チケットで目的と完了条件を明確にする
2. 実装前に設計の妥当性を確認する
3. 変更を一つの関心事に絞り、小さく実装する
4. テストや動作確認によって変更を検証する
5. Pull Request（以下、PR）で意図と判断理由を説明する
6. レビューで品質と知識を共有する

## ルールの優先順位

判断に迷う場合は、次の順で優先します。

1. セキュリティとデータ保護
2. 正しさとユーザーへの影響
3. 保守性とテスト容易性
4. DDD・クリーンアーキテクチャとの整合性
5. 実装の単純さ

ルール同士が競合する場合や、例外が妥当な場合は、チケットまたはPRに判断理由を記録します。

## ドキュメントの更新

- 実装とドキュメントに差異が生じる変更では、同じPRでドキュメントも更新する
- 新しいルールには、解決したい課題と採用理由を添える
- 実態に合わなくなったルールは放置せず、変更または削除する
- 例外が繰り返される場合は、個別対応ではなくルール自体を見直す
