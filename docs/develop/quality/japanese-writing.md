# 日本語執筆ガイド

## 目的

プロジェクト文書とAIエージェントが生成する日本語を、正確で簡潔な表現に統一します。読み手が目的、結論、根拠、次の行動を短時間で理解できることを重視します。

本ガイドは通常の成果物作成で守る必須規則です。詳しい説明、例、表記一覧、参考資料が必要な場合は、[日本語執筆ガイド参考](./japanese-writing-reference.md)を確認してください。

## 適用範囲

次の日本語へ適用します。

- README、開発ガイド、要件、規約、ADR、技術調査
- JiraチケットとPR
- コードコメントと利用者向けメッセージ
- AIエージェントの回答、提案、レビュー結果

既存文書は、内容を変更する機会に本ガイドへ合わせます。表記だけを統一する大規模な変更は、機能や設計の変更と分けます。

## 優先順位

規則が競合する場合は、次の順に優先します。

1. 正確さと安全性
2. 読み手が誤解しないこと
3. プロジェクト内の用語と文体の統一
4. 技術分野、製品名、APIの慣例
5. 本ガイドの一般的な表記規則

表記を統一するために、コード、コマンド、パス、識別子、API名、製品名、引用、固有名詞を改変しません。

## 共通チェックリスト

文書の作成、AIによる生成、レビューでは、次を確認します。

- [ ] 読み手、目的、求める判断または行動が明確である
- [ ] 結論、結果、目的などの重要な情報を先に示している
- [ ] 1文書で1つの主題、1段落で1つの論点を扱っている
- [ ] 事実、推論、判断、提案を区別している
- [ ] 事実には確認方法、判断と提案には根拠がある
- [ ] 複数の妥当な選択肢には、利点、欠点、推奨理由がある
- [ ] 不明な情報を推測で補わず、未確認と明記している
- [ ] 実施済みと未実施の検証を区別している
- [ ] 文体、用語、表記が統一されている
- [ ] 必要な情報を漏れなく記載し、目的に関係しない情報を含めていない
- [ ] 読み手の知識量に合わせて説明量を調整し、正確さ、安全性、判断に必要な根拠を省略していない
- [ ] 不要な情報、曖昧表現、重複がない
- [ ] コード、コマンド、識別子、固有名詞を改変していない
- [ ] 既存のテンプレートと用語を優先している

## 構成

- 結論、結果、目的を先に示し、その後に理由、根拠、詳細を続ける
- 概観から詳細へ進み、手順は時系列、比較は同じ観点で並べる
- 1文書で1つの主題を扱い、関心事が異なる場合は分ける
- 1段落で1つの論点を扱い、段落の先頭で要点を示す
- 1文には原則として1つの主要な内容を記載する
- 主体と行動、修飾語と被修飾語の関係を明確にする
- 二重否定と、対象が曖昧な指示語を避ける

## 事実と判断

| 種類 | 扱い |
| --- | --- |
| 事実 | コード、実行結果、一次情報などの確認方法または参照先を示す |
| 推論 | 根拠となる事実を示し、事実として断定しない |
| 判断 | 決定した内容と理由を示す |
| 提案 | 未決定であることを明確にし、利点、欠点、推奨理由を示す |

「おそらく」などの表現だけで不確実性を示しません。確認できない内容は「未確認」と明記します。

## 文体と表記

- 説明、手順、利用者向けの本文には敬体を使用する
- 要件、規則、Acceptance Criteria、チェックリストには常体を使用できる
- 同じ階層では敬体、常体、体言止めを混在させない
- 日本語の句読点には「、」と「。」を使用する
- 漢字、ひらがな、カタカナは全角、数字とアルファベットは半角にする
- 日本語と半角の数字・アルファベットの間には、原則としてスペースを入れない
- 日本語の補足には全角かっこ、コードや英語には半角かっこを使用する
- 常用漢字、現代仮名遣い、正しい送り仮名を使用し、読みやすいひらがなを優先する
- 外来語の語尾は原則として長音を省略しない
- 数量と順序には半角の算用数字を使用し、数値と日本語の単位の間にスペースを入れない
- 同じ概念には同じ用語を使用し、既存文書の表記へ合わせる

## Markdownと技術表記

- ファイル名、パス、コマンド、コード、識別子はコードスパンで囲む
- UI上のラベルや入力値は、必要に応じてかぎかっこで示す
- URLには内容がわかるリンクテキストを付ける
- 見出しの直後に、必要な説明を記載する
- 表は同じ項目を複数の対象で比較するときに使用する
- 重要な要件は注意書きだけで定義せず、本文または要件一覧にも記載する
- Markdown、コード、コマンドでは、その構文と技術分野の慣例を優先する

## 参考文書を確認する条件

通常は本ガイドだけを確認します。次の場合は[日本語執筆ガイド参考](./japanese-writing-reference.md)も確認します。

1. 表記または規則の適用に迷った場合
2. 本ガイドまたは参考文書を変更する場合
3. 文章品質を詳しくレビューする場合
