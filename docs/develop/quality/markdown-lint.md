# Markdown Lint

## 目的

Markdownの形式をプロジェクト内で統一し、文書の問題を編集時とレビュー前に検出します。

## 採用ツール

Markdownの検査には`markdownlint-cli2`を使用します。CLIとVS Code拡張が同じ設定ファイルを参照でき、ローカル環境と将来のCIで検査結果を統一できるためです。

依存関係はリポジトリルートの`package.json`と`package-lock.json`で管理します。製品のFrontend依存関係とは用途が異なるため、`frontend/`のパッケージ管理から分離します。

## 環境

Node.js 22以上とnpmを使用します。依存関係をリポジトリルートで取得します。

```shell
npm ci
```

## 実行方法

リポジトリ内のMarkdownを検査します。

```shell
npm run lint:markdown
```

検査対象と除外対象は`.markdownlint-cli2.jsonc`で管理します。`node_modules/`や生成物の`dist/`は検査しません。

## 規則

原則として`markdownlint`の既定規則を使用します。プロジェクトの文書構成に合わせて、次の規則だけを変更します。

- 1行の長さを制限する`MD013`を無効にする。日本語文書では、機械的な改行が文章の可読性を下げる可能性があるため
- ハードタブを検査する`MD010`は、コードブロックを対象外にする。Goコード例では、標準のインデントにタブを使用するため
- 見出しの重複を検査する`MD024`は、同じ親見出しの直下だけを対象にする。異なる章では、同じ小見出しを使用するため

規則の追加、無効化、例外指定を行う場合は、必要性と影響範囲を確認し、設定と本書を同じPRで更新します。

## VS Code推奨拡張

`.vscode/extensions.json`で次の拡張を推奨します。推奨拡張のインストールは強制しません。

- `DavidAnson.vscode-markdownlint`: `.markdownlint-cli2.jsonc`を参照し、Markdown編集中に問題を表示する
- `redhat.vscode-yaml`: YAML編集中に構文やスキーマの問題を表示する

保存時の自動修正は強制しません。自動修正による意図しない文書変更を避け、変更内容を確認してから反映するためです。
