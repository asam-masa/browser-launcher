# ストーリーポイント運用ガイド

## 目的

ストーリーポイントは、作業時間ではなく、作業の相対的な大きさをチームで認識するために使用します。個人の生産性評価や期限の確約には使用しません。

一人で開発する期間は記録を必須とせず、見積もりと実績の差から不確実性を学ぶ用途に限定します。

## 見積もりに含める要素

- **作業量**: 実装、テスト、レビュー、ドキュメント更新に必要な量
- **複雑さ**: 設計判断、状態遷移、依存関係の難しさ
- **不確実性**: 未経験の技術、仕様の曖昧さ、外部要因
- **リスク**: 既存機能への影響、切り戻しや検証の難しさ

担当者の熟練度や、会議・休暇などの予定はポイントに含めません。

## 使用する尺度

フィボナッチ数列の `1, 2, 3, 5, 8, 13` を使用します。

| ポイント | 相対的な目安 |
| --- | --- |
| 1 | 変更箇所が限定的で、方針と検証方法が明確 |
| 2 | 小さな変更だが、複数箇所の修正または軽微な判断が必要 |
| 3 | 標準的な変更で、実装・テストに複数の手順がある |
| 5 | 複数レイヤーにまたがる、または設計上の検討事項がある |
| 8 | 影響範囲や不確実性が大きく、分割を検討すべき |
| 13 | 見積もるには大きすぎる、または不明点が多い。原則として分割・調査する |

この表は絶対基準ではありません。見積もり済みの代表的なチケットを基準に、相対比較します。

## 見積もり手順

1. 目的、受け入れ条件、対象外を確認する
2. 実装・テスト・レビューまでの作業を想像する
3. 基準となるチケットと比較して各自が見積もる
4. 見積もりが割れた場合は、最大値と最小値の理由を共有する
5. 前提をそろえて再見積もりする

## 運用ルール

- ポイントを時間へ機械的に換算しない
- ポイントを担当者間の比較や評価に使わない
- 着手後に判明した事実で規模が大きく変わった場合、チケットを分割する
- 完了後のポイントを実績に合わせて変更しない
- 見積もり差が続く場合は、責任追及ではなく、見落とした作業や不確実性を振り返る
