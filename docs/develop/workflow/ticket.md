# チケット運用ガイド

## 目的

チケットは作業量の記録ではなく、解決する課題、期待する結果、作業範囲について合意するために使用します。

## チケットタイプ

| タイプ | 選択する状況 | 例 |
| --- | --- | --- |
| Story | ユーザーや利用者へ価値を提供する | 起動するブラウザを選択できる |
| Bug | 期待する振る舞いと実際の振る舞いが異なる | 指定した位置にウィンドウが表示されない |
| Task | 技術・運用上必要だが、直接的なユーザー価値として表しにくい | CIに静的解析を追加する |
| Spike | 実装方針を決めるための期限付き調査 | OSごとのウィンドウ制御方法を検証する |

大きな目的を複数のチケットに分ける必要がある場合は、Epicなどの親チケットを使用します。単に規模が大きいという理由だけでタイプを選ばず、作業の目的で判断します。

## 必須項目

チケットの作成には、[Jiraチケットテンプレート](../../templates/jira-ticket.md)を使用します。

| 項目 | 記載内容 |
| --- | --- |
| `Purpose` | なぜ取り組むのか、解決したい課題や得たい価値 |
| `As-Is` | 現在の状態と具体的な問題 |
| `To-Be` | 完了後に実現している状態 |
| `Acceptance Criteria` | 完了を客観的に判定できる条件 |
| `Out of Scope` | 今回対応しない事項 |
| `Progress` | 完了までに必要な作業内訳 |
| `Story Points` | 作業量、複雑さ、不確実性、リスクに基づく相対見積もり |
| `Remarks` | 制約、補足、判断理由、関連資料 |

`Progress` はチェックリストで作業内訳を示します。チケット全体の進行状態はJiraのステータスを正とし、進捗率を重複して管理しません。

### Story PointsとRemarks

- JiraのStory Pointsフィールドには、[ストーリーポイント運用ガイド](./story-point.md)に基づく数値を入力する
- `Remarks > Story Point Rationale` には、Story Pointの数値、作業量、複雑さ、不確実性、リスク、相対比較を記載する
- `Remarks > Additional Notes` には、制約、判断理由、関連資料など、Story Point以外の補足を記載する
- 比較対象となる既存チケットがない場合は、その旨を明記する

### Bugで追加する項目

- 再現手順
- 期待する結果と実際の結果
- 発生環境と発生頻度
- 影響範囲

### Spikeで追加する項目

- 明らかにしたい問い
- 調査の期限または上限時間
- 成果物（比較表、検証コード、ADRなど）
- 調査後に行う意思決定

## Acceptance Criteriaの書き方

実装方法ではなく、外部から確認できる結果を書きます。

```markdown
## Acceptance Criteria

- [ ] 対象ブラウザを一覧から一つ選択できる
- [ ] 未選択で起動しようとすると、選択を促すメッセージが表示される
- [ ] 選択したブラウザが指定したサイズで起動する
```

## 着手可能の条件（Definition of Ready）

`start-ticket-work` Skillを使用する場合も、次の条件を満たしてから作業ブランチを作成します。

- 目的と受け入れ条件が明確である
- 依存する作業と未決定事項が確認されている
- 一つのPRで扱えない規模なら、独立して検証できる単位へ分割されている

## 完了条件（Definition of Done）

- 受け入れ条件を満たしている
- 必要なコードレビューが完了している
- テスト、静的解析、ビルドが成功している
- 必要なドキュメントが更新されている
- 既知の制約や後続作業がチケットに記録されている
