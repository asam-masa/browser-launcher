# MVP受入テスト

## 目的

Browser LauncherのMVPが、[プロダクト要件](../product/requirements.md)のUC-01～UC-04を利用者視点で満たすことをWindows 11上で確認します。

本記録では、UI、Go・React間通信、ChromeおよびWindowsとの連携を含む一連の動作を検証します。個別の不具合修正、配布方法の決定および自動E2E Test基盤の導入は対象外です。

## 判定方法

各テストケースの結果には、次のいずれかを記録します。

| 結果 | 意味 |
| --- | --- |
| 成功 | 期待結果と実際の結果が一致した |
| 失敗 | 期待結果と実際の結果が一致しなかった |
| 未実施 | 検証を実施していない |
| 対象外 | 検証環境では条件を再現できず、代替確認も不要と判断した |

安全に再現できない異常系は、該当する自動テストの成功を代替確認として使用します。代替した場合は、対象のテスト名と、手動検証しない理由を実際の結果へ記録します。

## 手動テスト

### AT-01 有効な入力でChromeを起動して配置する

- 対応要件: UC-01
- 事前条件: プロファイル選択後に開く対象プロファイルの通常ウィンドウを閉じておく
- 入力値: 幅1000、高さ700、X座標100、Y座標100
- 操作手順:
  1. 幅、高さ、X座標およびY座標へ、使用可能領域内に収まる整数を入力する
  2. 「Chromeを起動」を選択する
  3. プロファイル選択画面が表示された場合は、使用するプロファイルを選択する
- 期待結果:
  - 通常のChromeウィンドウが新しく1つ開く
  - ウィンドウが指定した位置とサイズへ配置される
  - 完了状態と操作IDが表示される
  - 内部パス、OSコマンドおよびスタックトレースが表示されない
- 実際の結果:
  - 通常のChromeウィンドウが新しく1つ開いた
  - 位置とサイズが目視でおおむね要求どおりであることを確認した
  - 完了メッセージと操作IDが表示された
  - 完了状態は、最終計測値が要求値と一致した場合だけ返る実装であることを、`TestServicePlaceReportsBoundsMismatch`と`TestServicePlaceCompletesOnlyForMatchingBounds`で確認した
  - 内部パス、OSコマンドおよびスタックトレースは表示されなかった
- 結果: 成功

### AT-02 入力エラーをまとめて表示する

- 対応要件: UC-02
- 操作手順:
  1. 幅を空欄にする
  2. 高さへ`abc`を入力する
  3. X座標へ`1.5`を入力する
  4. Y座標へ`-1`を入力する
  5. 「Chromeを起動」を選択する
- 期待結果:

- 実際の結果:
  - Chromeは起動しなかった
  - 幅には「値を入力してください。」と表示された
  - 高さとX座標には「整数を入力してください。」と表示された
  - Y座標には「0以上の整数を入力してください。」と表示された
  - 各エラーは文字で表示され、入力欄を再編集できた
- 結果: 成功

## 自動テストで代替する異常系

### AT-07 Chromeを検出できない

- 対応要件: UC-03
- 手動検証しない理由: Chromeのアンインストール、移動またはシステム設定の変更を伴うため
- 代替確認:
  - Chrome未検出時に起動処理へ進まないApplicationまたはAdapterのテスト
  - 内部パスを含まない利用者向けメッセージのテスト
- 対象テスト:
  - `TestServiceLaunchClassifiesDetectionErrorsWithoutStartingProcess`
  - `TestWorkflowClassifiesLaunchFailureAndManagesTracking`
  - `TestLaunchOperationControllerCancelsAndGetsState`
- 実際の結果:
  - Chrome未検出を`chrome_not_found`へ分類し、プロセス起動へ進まないことを確認した
  - 「Chromeが見つかりませんでした。Chromeのインストール状況を確認してください。」と表示することを確認した
  - Windows上で`go test ./...`が成功した
- 結果: 成功

### AT-08 Chromeの起動または配置に失敗する

- 対応要件: UC-04
- 手動検証しない理由: OSまたはChromeの故障状態を安全かつ再現可能に作ることが難しいため
- 代替確認:
  - 起動、追跡または配置の失敗を終端状態へ変換するApplicationのテスト
  - UIが安全なエラーメッセージを表示し、入力を保持して再実行できることのテスト
- 対象テスト:
  - `TestWorkflowClassifiesLaunchFailureAndManagesTracking`
  - `TestWorkflowPreservesPlacementFailureResult`
  - `TestServiceMapsWorkflowFailures`
  - `TestServiceAllowsRestartAfterFinish`
  - `TestLaunchOperationControllerReturnsSafeStartErrors`
  - `開始失敗では安全な再試行メッセージを表示する`
  - `起動失敗後も入力値を保持して再実行できる`
- 実際の結果:
  - 起動、追跡または配置の失敗を終端状態へ変換し、内部エラーを含まないメッセージを表示するテストは成功した
  - 終端後に新しい操作を開始できるApplicationのテストは成功した
  - 失敗状態を受信した後も4項目の入力値を保持し、起動ボタンを再び選択できることをFrontendテストで確認した
  - 同じ入力値で再実行すると、新しい起動要求が送信されることをFrontendテストで確認した
  - 内部エラーを安全な公開メッセージへ変換することを`TestLaunchOperationControllerReturnsSafeStartErrors`と`TestLaunchOperationControllerCancelsAndGetsState`で確認した
  - 開始時の内部エラーがUIへ表示されないことを`開始失敗では安全な再試行メッセージを表示する`で確認した
  - 追加したFrontendテストがLinuxとWindows 11の両環境で成功した
- 結果: 成功

## 未確認事項と既知の制約

- ユーザー単位とシステム単位のChromeが共存する環境での検出優先順位は、本受入テストの対象外です
- 検証に使用したGoogle Chromeが安定版チャネルであることは未確認です
- セカンダリディスプレイ、マルチディスプレイおよび100%以外の表示倍率は、本受入テストの対象外です
- Windows向けアプリケーションの配布、インストーラーおよびコード署名は未決定です
- npmは`esbuild@0.25.12`のインストールスクリプトが`allowScripts`で
  未承認であると警告します
